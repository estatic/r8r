# r8r Node-Type Metadata System (Plan 8.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every node type compiler-enforced identity metadata (display name, icon, category, description, accepted credential types, output port labels), surfaced through a richer `/rest/node-types` response and a new per-instance output-ports endpoint, consumed by the canvas, add-node menu, and credential picker.

**Architecture:** Five new methods on the existing `Node` trait (three required, two defaulted) turn every node implementation into its own source of truth for its metadata — no separate registry to drift out of sync. The backend exposes this via two endpoints; the frontend fetches it once into a Pinia store and reads from there everywhere a node type is displayed or a credential is picked.

**Tech Stack:** Rust/Axum backend (`src/node.rs`, `src/nodes/*.rs`, `src/api/node_types.rs`), Vue3/TS/Pinia frontend (`frontend/src/stores/nodeTypes.ts`, `frontend/src/components/{AddNodeMenu,WorkflowCanvas,CredentialPicker,NodeConfigPanel}.vue`).

**Spec:** `docs/superpowers/specs/2026-09-21-r8r-node-type-metadata-design.md`

## Global Constraints

- `display_name()`, `description()`, `category()` have **no default** on the `Node` trait — every implementor must provide them. This means the trait change and updating all 15 node files are **one inseparable unit**: the crate does not compile with only the trait changed. Task 1 covers both together.
- `icon()` defaults to `"⚙️"`, `credential_types()` defaults to `&[]`, `output_ports()` defaults to `vec!["main".to_string()]` — only override these where the metadata table below says otherwise.
- No change to `NodeInstance`, `Connection`, or any stored workflow data — this is additive metadata only, no migration.
- Out of scope (do not implement): multi-handle canvas rendering (Plan 8.3), structured credential *data* forms (Plan 8.4), the raw-JSON parameters textarea, backend credential-type validation.

```rust
}
```

Add the five methods to the `Node` trait, after `resolves_parameters`:

```rust
    /// Human-readable name shown in the canvas and add-node menu, e.g.
    /// "Telegram Trigger" for `telegram.trigger`. No default -- every node
    /// type must declare one.
    fn display_name(&self) -> &'static str;

    /// One sentence describing what the node does, shown in the add-node
    /// menu. No default.
    fn description(&self) -> &'static str;

    /// Groups this node type in the add-node menu and drives canvas
    /// styling. No default.
    fn category(&self) -> NodeCategory;

    /// A single emoji shown next to the node's name.
    fn icon(&self) -> &'static str {
        "⚙️"
    }

    /// Credential type string(s) this node's `auth.credential_id` accepts,
    /// e.g. `&["telegramApi"]`. Empty means "no credential" for a node with
    /// no `auth` parameter, or "any credential" for one (like
    /// `core.httpRequest`) whose own `auth.type` parameter picks the shape
    /// at runtime -- the credential picker treats an empty list as "don't
    /// filter", not "don't allow".
    fn credential_types(&self) -> &'static [&'static str] {
        &[]
    }

    /// This node instance's current output ports, labeled. Takes
    /// `parameters` because a port count can be data-dependent (see
    /// `core.switch`'s override in Task 1); every other node type ignores
    /// the argument and returns a fixed list.
    fn output_ports(&self, parameters: &serde_json::Value) -> Vec<String> {
        vec!["main".to_string()]
    }
```

```rust
    fn display_name(&self) -> &'static str {
        "Switch"
    }
    fn description(&self) -> &'static str {
        "Routes items to one of several outputs based on matching a value against a list of cases."
    }

    fn output_ports(&self, parameters: &serde_json::Value) -> Vec<String> {
        let case_count = parameters.get("cases").and_then(|v| v.as_array()).map(|a| a.len()).unwrap_or(0);
        (0..case_count)
            .map(|i| format!("case {i}"))
            .chain(std::iter::once("default".to_string()))
            .collect()
    }
```

Replace the entire file with:

```rust
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::http::StatusCode;
use axum::response::IntoResponse;
use axum::Json;

#[derive(serde::Serialize)]
pub struct NodeTypeMeta {
    pub type_name: String,
    pub display_name: String,
    pub icon: String,
    pub category: crate::node::NodeCategory,
    pub description: String,
    pub credential_types: Vec<String>,
    pub output_ports: Vec<String>,
}

fn meta_for(name: &str, node: &dyn crate::node::Node) -> NodeTypeMeta {
    NodeTypeMeta {
        type_name: name.to_string(),
        display_name: node.display_name().to_string(),
        icon: node.icon().to_string(),
        category: node.category(),
        description: node.description().to_string(),
        credential_types: node.credential_types().iter().map(|s| s.to_string()).collect(),
        output_ports: node.output_ports(&serde_json::json!({})),
    }
}

pub async fn list_node_types(
    State(state): State<AppState>,
    super::workflows::AuthUser(_user_id): super::workflows::AuthUser,
) -> impl IntoResponse {
    let metas: Vec<NodeTypeMeta> = state
        .registry
        .type_names()
        .into_iter()
        .filter_map(|name| state.registry.get(name).map(|node| meta_for(name, node)))
        .collect();
    Json(metas).into_response()
}

#[derive(serde::Deserialize)]
pub struct OutputPortsRequest {
    #[serde(default)]
    pub parameters: serde_json::Value,
}

pub async fn output_ports_for_type(
    State(state): State<AppState>,
    super::workflows::AuthUser(_user_id): super::workflows::AuthUser,
    Path(type_name): Path<String>,
    Json(payload): Json<OutputPortsRequest>,
) -> impl IntoResponse {
    match state.registry.get(&type_name) {
        Some(node) => Json(serde_json::json!({"output_ports": node.output_ports(&payload.parameters)})).into_response(),
        None => StatusCode::NOT_FOUND.into_response(),
    }
}
```

```typescript
import { defineStore } from 'pinia'
import { api } from '../api/client'
import type { NodeTypeMeta } from '../types/domain'

export const useNodeTypesStore = defineStore('nodeTypes', {
  state: () => ({
    types: [] as NodeTypeMeta[],
    loaded: false,
    portsCache: {} as Record<string, string[]>,
  }),
  actions: {
    async fetchAll() {
      if (this.loaded) return
      this.types = await api.get<NodeTypeMeta[]>('/rest/node-types')
      this.loaded = true
    },
    async portsFor(typeName: string, parameters: Record<string, unknown>): Promise<string[]> {
      const key = `${typeName}:${JSON.stringify(parameters)}`
      const cached = this.portsCache[key]
      if (cached) return cached
      const result = await api.post<{ output_ports: string[] }>(`/rest/node-types/${typeName}/output-ports`, { parameters })
      this.portsCache[key] = result.output_ports
      return result.output_ports
    },
  },
})
```
