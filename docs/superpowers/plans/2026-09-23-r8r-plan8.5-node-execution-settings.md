# Per-Node Execution Settings (Plan 8.5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-node retry (fixed wait), opt-in per-attempt timeout, and continue-on-fail, stored in `NodeInstance.settings`, enforced by the engine, validated by the API, and editable in the node config panel.

**Architecture:** A `NodeSettings` struct on `NodeInstance` (`#[serde(default)]`, so old workflows load unchanged). `src/engine.rs` gains `run_node_with_policy()` wrapping `node.execute()` with a retry/timeout loop, and its failure arm gains a `continue_on_fail` branch after the existing error-route branch. `src/api/workflows.rs` gains `validate_nodes()` called by create/update. `NodeConfigPanel.vue` gains a Settings section.

**Tech Stack:** Rust (tokio, axum, serde), Vue 3 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-23-r8r-node-execution-settings-design.md`

## Global Constraints

- `retry: None` = exactly one attempt; `timeout_ms: None` = no timeout (default).
- Ranges: `max_tries` 2..=10, `wait_ms` 0..=60000, `timeout_ms` 1..=3600000.
- Timeout is per attempt; no wait after the final attempt.
- Exhausted retries with `max_tries > 1` → `NodeError::ExecutionFailed("failed after {max_tries} attempts: {last message}")`, where an `ExecutionFailed` last error contributes its inner message (not its Display, to avoid a doubled `node execution failed: ` prefix); timeout → `timed out after {ms}ms`.
- Failure precedence: error connection → `continue_on_fail` (error item on port 0) → workflow fails `node {id} failed: {msg}`. `on_node_errored` is called in all three.
- No new `ExecutionObserver` events. Parameter-resolution errors are neither retried nor continued.
- API validation messages: `node {id}: retry.max_tries must be between 2 and 10`, `node {id}: retry.wait_ms must be between 0 and 60000`, `node {id}: timeout_ms must be between 1 and 3600000`.

## Review Focus

- A workflow saved before this change (no `settings` key in stored JSON) must still load and run identically — pinned by the Task 1 serde test and the Task 4 round-trip test.
- A node timing out on every attempt must still honor retries and the wait (not return after the first timeout) — pinned in Task 2 (`timeout_is_retried`).
- `continue_on_fail` on a multi-port node (e.g. `core.if`) must not deliver the error item to non-zero ports — pinned in Task 3 (`continue_on_fail_only_feeds_port_zero`).
- An invalid PUT must not partially persist — pinned in Task 4 (stored workflow unchanged after 400).
- Opening a node saved without settings must not show retry as enabled, and a stored `wait_ms: 0` must not be replaced by 1000 — pinned in Task 5.

```rust
/// Runs one node under its `NodeSettings`: each attempt optionally bounded
/// by `timeout_ms`, retried up to `retry.max_tries` with `retry.wait_ms`
/// between attempts (never after the last). Default settings = exactly one
/// untimed `execute()` call, i.e. the pre-Plan-8.5 behavior.
async fn run_node_with_policy(
    node: &dyn crate::node::Node,
    ctx: &NodeExecutionContext,
    settings: &crate::domain::NodeSettings,
) -> Result<crate::node::NodeOutput, crate::node::NodeError> {
    let max_tries = settings.retry.as_ref().map_or(1, |r| r.max_tries);
    let wait = std::time::Duration::from_millis(settings.retry.as_ref().map_or(0, |r| r.wait_ms));
    let mut attempt = 1;
    loop {
        let result = match settings.timeout_ms {
            Some(ms) => tokio::time::timeout(std::time::Duration::from_millis(ms), node.execute(ctx))
                .await
                .unwrap_or_else(|_| Err(crate::node::NodeError::ExecutionFailed(format!("timed out after {ms}ms")))),
            None => node.execute(ctx).await,
        };
        match result {
            Ok(output) => return Ok(output),
            Err(e) if attempt >= max_tries => {
                if max_tries == 1 {
                    return Err(e);
                }
                // Unwrap the message so the Display prefix ("node execution
                // failed: ") isn't repeated. NodeError has one variant, so
                // this let is irrefutable; add match arms if that changes.
                let crate::node::NodeError::ExecutionFailed(last) = e;
                return Err(crate::node::NodeError::ExecutionFailed(format!("failed after {max_tries} attempts: {last}")));
            }
            Err(_) => {
                tokio::time::sleep(wait).await;
                attempt += 1;
            }
        }
    }
}
```
